# PDR 文档集

PDR（Product Design Requirements）= 产品最终功能与形态规格书（目标态）：描述产品最终要长成什么样、由哪些模块构成、各模块对外契约与机制设计。

## 最终目标

TodoList 是一个 Windows 桌面待办工具：本地优先，以纯文本 YAML 文件为唯一事实源；支持经典待办能力（清单与任务、组织、提醒、检索、桌面集成、历史）；文件格式对 agent 友好（可读、可写、稳定 ID、未知字段宽容），数据目录可交由 git / 网盘直接管理。

## 组织约定

- 编号即阅读顺序：每模块 = 规格层（`00-README` / `01-spec` / `02-interfaces` / `03-nfr`）+ 现状快照（`04-current.md`，与目标的差距用于派生 issue）+ 设计子区（`design/`，机制级设计，不参与编号）。
- 模块外区：架构总纲、调研等跨模块材料按需单列，不占模块编号。

## 阅读顺序

先读 `10-app/01-spec.md`（功能目标与 v1 切片范围）与 `10-app/02-interfaces.md`（文件格式契约——app 与外部 agent 的共同依据），再看 `10-app/03-nfr.md` 与 `10-app/04-current.md`。

## 新增模块

- 在 `docs/pdr/` 下建编号目录（编号沿用阅读顺序，不插号）；
