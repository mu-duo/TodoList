## 关键结论与已知问题

- 冲突策略：同一任务并发修改以磁盘后写为准（ADR-0003）；极端场景可能丢一次改动（窗口极小）。
- v1 无内置备份（ADR-0003）；建议数据目录纳入 git / 网盘。
- move_list 采用整体重编号（会重写全部清单文件、YAML 排版被序列化器规范化）；功能正确，后续可优化。
- 删除：任务 / 子任务**直接删**（无确认）；**清单删除用自定义确认模态**（默认焦点在「取消」，`Esc` / 遮罩 / 取消均可退）；**仍无撤销**（触屏下任务行删除图标常显，一按即删 —— 残留风险）。
- 提醒（FR-APP-08，1.6.0 已实现并本地验证）：默认四档（due 前 7 天 / 1 天 / 1 小时 + 到期；`reminder: false` 关闭），启动 / 手动刷新同步快照，无 watcher；load_lists 读盘到 worker ack 串行。目录 / 清单读取不完整（包括结构无效或任务项被跳过）时，全局 fail closed 暂停提醒、不 reconcile / send、不更新或清理 checkpoint；成功完整刷新恢复，部分清单仍可展示并提示提醒已暂停。ledger 含 `attempted` keys、`observed`（首帧标记）与完整快照唯一 task ID 的 `last_status`（`true=open`、`false=非 open`）；首帧（新建 / 改 due / 升级 / 重开提醒）静默 claim 已过提前档、首帧已过的到期档补一条；跨重启观察到 done→open 时原子 claim 全部已过档、仅保留未来事件。应用关闭期间完整发生的 open→done→open 无法识别；启动按最终 open 做普通 catch-up（已确认语义）。任务 / 清单文件写入持进程级锁（通知线程写回与命令并发不丢更新）。通知「不再提醒」按钮点击仅在通知停留屏幕时有效（进通知中心 / 应用退出后无效，Tier 1 已接受）；点通知本体前置窗口。账本只记录本机发送尝试，不是 OS 展示 / 用户送达确认；当前无提醒状态面板。Windows permission API 无法探测系统设置或专注助手屏蔽，toast 为 best effort。
