# 回退：tdd

> 当需要调用 `tdd` 但环境未安装该 skill 时，按本文执行。

> 内部回退（精简版），裁剪自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 tdd（MIT License, Copyright (c) 2026 Matt Pocock）。若环境已安装同名完整 skill，请优先使用完整版。

以测试先行的方式构建功能或修 bug：red → green 循环。

## 步骤

1. **先定 seam**：seam 是你据以测试的公共边界（无需伸手进内部即可观察行为）。写测试前先写下待测 seam 并与用户确认；**未确认的 seam 上不写测试**。
2. **红**：写一个失败的测试。测试通过公共接口验证行为，读起来像规格（描述 WHAT 而非 HOW），每个测试一个逻辑断言。不要 mock 内部协作者，不要走旁路（绕过接口查数据库）。
3. **绿**：只写刚好让这个测试通过的实现。不加预判未来测试的投机功能。
4. **重复**：以**纵向切片**推进——一个测试 → 一个实现 → 重复，每个测试是回应上一轮所学的一发**曳光弹**。不要「先写完所有测试再写所有实现」。
5. **重构**不属于 red → green 循环；它属于评审阶段（代码评审；若环境有 `code-review` 则按其执行）。

探索代码库时读 `CONTEXT.md`（若存在），让测试名匹配领域语言，并遵守相关 ADR。

## 期望值

期望值必须来自**独立真相源**：已知良好的字面量、算好的例子、规格。不要以代码的算法重算期望值（`expect(add(a, b)).toBe(a + b)`、手工按同样方式推出的快照）——那是同义反复，只会通过，永远无法与代码唱反调。

## mock

**只在系统边界 mock**：外部 API、数据库（有时——优先测试库）、时间/随机性、文件系统（有时）。**不要 mock** 你自己的类/模块、内部协作者、任何你控制得了的东西。

便于 mock 的边界设计：用依赖注入把外部依赖传进来；优先 SDK 式接口（每个操作一个具体函数）而非带条件的通用 fetcher。

## 反模式速查

- 耦合实现：重构后行为未变测试却坏。
- 同义反复：断言由构造保证为真。
- 横切切片：批量测试验证想象的行为，测的是形状而非用户行为。

当 seam 形状本身存疑（模块多深、seam 在哪、接口暴露什么）时，参考 `codebase-design` 的 module / interface / depth / seam / adapter / leverage / locality 词汇。
