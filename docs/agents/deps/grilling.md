# 回退：grilling

> 当需要调用 `grilling` 但环境未安装该 skill 时，按本文执行。

> 内部回退（精简版），裁剪自 [mattpocock/skills](https://github.com/mattpocock/skills) 的 grilling（MIT License, Copyright (c) 2026 Matt Pocock）。若环境已安装同名完整 skill，请优先使用完整版。

> `grill-me` 只是本流程的入口别名，本身不含独立流程；`grill-with-docs` = 本流程 + `domain-modeling`（见同目录 `domain-modeling.md`），两者交织进行。

持续追问用户，直到对方案达成共同理解。把它建模成一棵**设计树**：每个决策分叉出依赖它的子决策。用**轮次**遍历这棵树。

## 步骤

1. **算 frontier**：frontier = 前置条件已确定、现在就能问的问题（不必臆测尚未听到的答案）。答案依赖本轮其他未决问题者，属于后续轮次。
2. **整轮提问**：把当前 frontier 一次性全部提出；每个问题编号，并给出**你推荐的答案**。
   ```
   ❓ **Q1** - **<问题标题>**：<正文，可多段、可含多选项>

   ➡️ <推荐答案>

   ---

   ❓ **Q2** - **<问题标题>**：<正文>

   ➡️ <推荐答案>
   ```
3. **等用户回答**，然后回到第 1 步重算 frontier：已确定的决策把 frontier 向外推，解锁下游问题。
4. **拆事实与决策**：环境中的事实（文件系统、工具、文档）由**你**派子 agent 去查，绝不问用户；只有依赖该探查的下游问题需要等回报，frontier 其余问题现在就问。决策一律摆到用户面前并等待，不替用户拍板。
5. **收尾**：frontier 为空（每条分支都走过、无默认假设）即结束。

## 硬规则

- 在用户确认已达成共同理解之前，**不要动手实施**。
- 绝不问用户你本可以自己查的事实。
