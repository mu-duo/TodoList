# 任务详情元数据与截止提醒

> Status: done（本地验证通过；尚未提交 / 推送，等待用户推送）｜ 责任: agent ｜ 创建: 2026-10-13 ｜ 关联: PDR `docs/pdr/10-app/01-spec.md` FR-APP-06/07/08；`docs/pdr/10-app/02-interfaces.md`

## 背景与目标

用户主要用 TodoList 管理工作/项目与学习/研究任务。优先级使用频率低，但用户希望可选编辑；真实截止日期有明确用途；标签偶尔用于上下文；提醒有价值。优化现有任务详情页，保留层级结构；先交详情字段可视切片供用户肉眼复核，再继续提醒调度实现。

### 已对齐范围

- 优先级：可选 `high / medium / low`，无默认值，可清除。
- 截止：可选本地日期或本地日期时间（`YYYY-MM-DD` / `YYYY-MM-DDTHH:MM`）；新编辑器兼容并可编辑旧格式。
- 标签：可输入新标签，并从所有已加载清单建议已有标签；标签搜索留后续。
- 截止通知：日期值在截止日当地 09:00 通知；日期时间值在指定时刻通知。可选的单次提前提醒为截止前 1 个本地日历日，沿用同一当地时刻（日期值仍为 09:00）。
- 提醒仅依赖应用进程运行；最小化时继续，关闭主窗后停止。应用启动或手动刷新时，对仍未完成且有未尝试到期事件的任务，每个任务最多发起一次 catch-up，并记录本机发送尝试，避免之后重复；该记录不代表 Windows 实际展示或用户已送达。未来尚未到时的事件仍照常调度。
- 提醒设置以 task YAML `reminder_offset_days: 1` 随任务保存；通知发送尝试记录只留在本机应用配置目录。
- 外部修改按现有机制同步：应用启动或用户手动刷新时重建提醒计划；本轮不加入文件监听/自动重载（FR-APP-20）。
- 夏令时不存在的当地时刻顺延到下一有效时刻；重复时刻取第一次，仅发送一次。
- 通知与发送尝试 ledger 无法原子提交，选择 at-most-once：权限确认后先持久化发送尝试，再调用 Windows 通知；ledger 写入失败不发送。崩溃窗口可能漏发一次，不承诺严格 exactly-once。
- Windows 通知为最佳努力：插件桌面权限 API 恒报 `Granted`，无法检测 Windows 通知设置/专注助手是否屏蔽；`show()` 成功不保证用户实际看见。
- ledger 事件键按 `task id + 规范化 due + event type (advance/due)` 去重；检测到跨清单重复 task id 时隔离有歧义的提醒，不静默合并。一次启动/刷新若同一任务多个提醒已过，只补一条（优先 due），并只记账本次覆盖的已过事件；未来事件照常发送。
- 截止日期改变后重排；清除截止日期时同时清除提前提醒设置；完成/删除时取消待发提醒；取消完成后仅重排未来且未送达事件。
- 不改任务行/逾期高亮（FR-APP-10）、重复任务（FR-APP-09）、全局标签搜索或详情页整体重设计。

## 完成判据

- 详情页中可编辑优先级、截止日期/时间、标签与提前一天提醒；现有标题/备注/子任务键盘、即时保存及窄屏行为无回归。
- 保存仅补丁目标任务字段，保持未知 YAML 字段及其它字段；截止支持两种既有格式。
- 运行期间系统通知遵守上述本地时间、提前量、完成/删除、清除/变更日期规则；进程退出时不承诺后台通知。
- 启动与手动刷新补发规则去重；提醒配置与本机送达状态分离。
- 应用启动或手动刷新后读取外部文件变更并同步提醒计划；不实现自动文件监听。
- 重复 task id、ledger 写失败、通知权限拒绝、送达尝试崩溃窗口均有明确 fail-safe 行为与测试。
- UI 明确说明 Windows 系统设置可能屏蔽通知，不把插件调用成功表述为已显示/已送达。
- Rust 调度/存储测试、前端构建与项目检查通过；更新 PDR 现状与接口契约。
- UI 可视切片先交用户复核；收到复核意见前不继续到提醒运行时阶段。
