# 删除回收站（「已删除」24 小时暂存）

> Status: done（用户验收通过 2026-10-29） ｜ 责任: agent ｜ 创建: 2026-10-29 ｜ 关联: FR-APP-37、ADR-0010、`docs/product/10-app/02-interfaces.md` §2.1 / §3

## 背景与目标

任务与清单的删除当前是物理删除（任务从 `tasks` 数组移除、清单直接 `fs::remove_file`），无撤销手段。删除是高频高危操作，误删不可挽回。

目标：把删除改为「移入回收站」：

- 被删除的任务与清单转移到一个独立的保留文件，24 小时内可恢复；
- 应用运行期间与下次启动时自动清理超过 24 小时的条目（真删除）；
- 侧栏新增固定「已删除」入口（与「已完成」同级、同款虚拟视图，不可重命名 / 排序 / 普通删除）；
- 恢复任务时若原清单已不存在，提示用户选择目标清单；恢复清单时若原文件名被占用，自动使用不冲突的文件名。

## 已对齐范围（2026-10-29 用户确认）

1. **落盘形态**：独立保留文件 + 固定虚拟入口。保留文件为 `lists/.trash.yaml`，loader 不把它当普通清单；任务 / 清单内容真实移入该文件。
2. **覆盖范围**：任务删除 + 清单删除（整份清单连同其任务一起进入回收站）。子任务删除本轮不覆盖。
3. **恢复与清理**：单项恢复 + 自动 24h 清理；不提供手动「清空回收站」。过期条目在应用启动时、运行中定时、以及每次读取回收站时清理。
4. **原清单不存在**：恢复任务时提示选择目标清单；目标清单也被删除时由用户在现有清单中选择。
5. **布局**：类似「已完成」——按来源清单分组、组头「名称 · 数量」，任务行展示标题与剩余时间、行内「恢复」；删除的清单单独成组（整份清单一行，显示任务数）。
6. **行宽与右键（2026-10-29 追加）**：回收站任务行外宽 / 内边距与普通任务卡一致；右侧固定显示剩余时间 + 「恢复」；任务行右键支持「彻底删除」（确认后立即真删除）。
7. **分组折叠（2026-10-29 追加）**：来源清单分组支持折叠；除没有时间标签外与「已完成」分组折叠行为一致，折叠集合持久化到 `settings.yaml` 的 `trash.collapsed`。

## 完成判据

- 删除任务：从原清单文件移除，出现在 `lists/.trash.yaml` 的 `tasks` 中，保留任务全部字段、原清单文件名与显示名、删除时间；普通视图不再显示。
- 删除清单：原文件被移入 `.trash.yaml` 的 `lists`（完整清单内容），原文件消失；侧栏不再显示。
- 「已删除」固定入口：显示可见条目数（任务 + 清单），与「已完成」并列；进入后按来源清单分组，任务显示剩余时间与「恢复」；删除的清单显示名称 / 任务数 / 「恢复」。空态有提示。
- 恢复任务：原清单存在 → 直接恢复到该清单末尾；原清单不存在 → 弹出目标清单选择；恢复后条目从回收站移除，任务回到普通视图；同 id 冲突时报错且不写盘。
- 恢复清单：重建清单文件；原文件名被占用时使用不冲突的新文件名；恢复后条目从回收站移除。
- 24h 清理：`deleted + 24h <= now` 的条目被移除；`deleted` 无法解析的条目保留（不误删）；清理后若回收站为空则删除 `.trash.yaml`（不残留空文件）。
- 删除清单确认文案改为「可恢复」语义；删除任务后给出轻量提示（可进入「已删除」）。
- 回收站任务行与普通任务卡同宽，右侧固定剩余时间 + 「恢复」；任务行右键「彻底删除」经确认后立即真删除。
- 「已删除」来源清单分组可折叠，状态存 `settings.yaml` 的 `trash.collapsed`，重启保持；除无时间标签外与「已完成」折叠行为一致。
- 未知字段、其它任务、外部手改的回收站条目均宽容保留。
- 验证：Rust 单测覆盖删除 / 恢复 / 清理 / 冲突 / 保留未知字段；`trash.ts` 纯逻辑断言；`pnpm build`；`cargo test --all-targets`；`cargo clippy --all-targets -D warnings`；`git diff --check`。

## 设计要点（实现契约）

- 保留文件：`lists/.trash.yaml`（常量 `TRASH_FILE`），schema 见 interfaces §2.1；`load_lists_from` / `read_ordered_lists` / `ensure_data_dir` 均跳过该文件。
- 写序：先写回收站、后移除原位置；移除失败时回滚回收站。多文件操作持既有进程级写锁。
- 恢复：先写目标清单、后移除回收站条目；回收站写失败时回滚目标。
- `delete_task` / `delete_list` 命令名与参数不变（前端删除入口无需改调用，仅改提示）；新增 `load_trash` / `restore_task` / `restore_list`。
- 过期清理：`load_trash` 内顺带清理；启动时 + 运行中每 10 分钟后台清理一次。
