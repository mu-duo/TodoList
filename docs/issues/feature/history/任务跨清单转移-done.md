# 任务跨清单转移

> Status: done（用户验收通过 2026-10-13；尚未提交 / 推送）｜ 责任: agent ｜ 创建: 2026-10-13 ｜ 关联: PDR `docs/pdr/10-app/01-spec.md` FR-APP-04（跨清单移动）、FR-APP-18

## 背景与目标

现状只有单清单内任务排序（`reorder_task`）：后端没有跨清单移动命令，前端任务区与清单条是两个独立拖拽域，也没有右键入口。本切片新增两种转移方式——任务右键「移动到清单」子菜单与拖拽到清单条——任务 id 与全部字段保留。

## 已对齐范围（2026-10-13 grilling 定案）

- 右键：任务右键菜单新增「移动到清单 ▸」子菜单，列出除任务所在清单外的全部真实清单（侧栏顺序）；「已完成」为虚拟聚合，不出现；没有可选目标时不显示该项。
- 拖拽：把任务拖到「清单条」中的目标清单项 = 移动到该清单末尾；源清单自身不是有效目标；拖拽仅普通清单视图可用（「已完成」视图为只读，不开放拖拽）。
- 两种入口的落点统一为「目标清单末尾」，不提供目标清单内部插入位置。
- 右键在普通视图与「已完成」视图都可用；无确认、无撤销、成功静默（任务从源视图消失）；失败显示错误。
- 任务 id 不变；字段与未知 YAML 字段全保留（Value 级移动）。

## 完成判据

- 右键 / 拖拽两条路径都能把任务移到目标清单末尾：源文件移除、目标文件出现、id 不变（FR-APP-04 判据）。
- 目标清单已存在同 id、源任务不存在、源=目标等情况明确报错且不产生损坏文件；写失败不丢任务（写序与回滚见技术备注）。
- 移动后视图刷新一致；被移动任务若正打开在详情面板，行为明确（不残留指向源清单的编辑）。
- 后端 storage 测试、`cargo check`、Clippy、`pnpm build` 通过；交互验证给出可复核证据（含拖拽高亮与落点）。

## 结果

- 右键「移动到清单 ▸」与拖拽到清单条两条入口可用；落点 = 目标清单末尾，id 与全部字段（含未知）保留；拖拽目标高亮、取消清除；仅普通视图开放拖拽，「已完成」视图仅右键可用。
- 后端 `move_task`：源≠目标 / 源含任务 / 目标无同 id 校验；先目标追加、后源移除，源失败回滚目标（回滚失败明确报错、绝不静默）。

## 技术备注

- 建议命令签名：`move_task(list_file, task_id, to_list_file)`；storage 镜像 `delete_task_in` / `find_task_mut` 的 Value 级补丁模式。
- 双文件写序：先向目标追加（原子写），再自源移除（原子写）；源移除失败时尝试回滚目标内容，回滚成功则返回错误（状态未变），回滚也失败返回明确错误（可能出现同 id 双份，绝不静默）。
- 拖拽实现建议：任务拖拽期间对清单条项做指针命中测试（沿用现有任务 DndContext，避免合并为单一全局 DndContext 的大重构）；不得回退既有键盘拖拽 / 触屏长按 / 清单条自身排序。
- 已知限制（不在本切片解决）：Agent 运行中的任务转移无特殊保护；本机拖拽交互不支持键盘跨清单（键盘用户走右键子菜单）。
