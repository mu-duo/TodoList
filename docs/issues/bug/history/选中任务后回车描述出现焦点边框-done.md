# 选中任务后按回车，任务描述仍显示焦点边框

> Status: doing ｜ 责任: agent ｜ 创建: 2026-10-10 ｜ 关联: `窄屏Esc返回后任务描述出现边框.md`（同源：`button:focus-visible` 焦点环）；**待确认**

## 现象（用户报告）
**鼠标点击**选中某任务（此时 description 无边框）→ **按回车** → 任务描述上**出现 / 保留边框**（用户诉求：不应出现）。

## 假设（待 CDP 确认）
与 RC3 同源：`.task-open` 是 `<button>`。指针点击后焦点落在其上（`:focus-visible` **不**命中 → 无边框）；随后按 `Enter` 属**键盘交互** → 浏览器重估焦点可见性 → 命中 `button:focus-visible{outline:2px solid var(--accent);outline-offset:2px}`（`App.css:219-222`）→ 描述上出现 2px 靛蓝焦点环。
需排除的另一种可能：用户看到的是 `.task-card.is-selected` 的**选中态边框**（`App.css:422-425`，设计使然）。

## 待确认
- 用户流程（点击行 → Enter）：`.task-open` 的 `:focus-visible` 是否命中、`outline` computed 值；`.task-card` 的 `is-selected` 与边框值——**分清焦点环与选中边框**。
- 对照：纯指针（只点击）应无边框；纯键盘（Tab + Enter）应**保留**焦点环。
- 详情打开后焦点是否仍留在行的 `.task-open`（是否缺少"焦点交给面板"的编排）。

## 完成判据
- 选中任务后按回车：**不出现**意外焦点边框。
- **键盘用户经 Tab 导航时仍保留可见焦点指示**（不得全局 `outline: none`）。
- 详情打开期间的焦点归属明确，`Tab` 顺序符合直觉。
